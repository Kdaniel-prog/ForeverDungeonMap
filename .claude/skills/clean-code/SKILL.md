# Clean code in ForeverDungeonMap (Lua 5.1, WoW addon)

The owner's rules, ported from demo2 (C#/Godot) to Lua. They apply to every agent and
every file. When a rule here and a habit disagree, the rule wins.

## 1. No abbreviations. Anywhere.
Names are spelled out: locals, functions, table keys, frame keys, file names, SavedVariables.

| no | yes |
|---|---|
| `btn`, `lbl`, `tex`, `fs` | `button`, `label`, `texture`, `fontString` |
| `q`, `b`, `d`, `e` (as data) | `quest`, `boss`, `dungeon`, `entrance` |
| `inst`, `idx`, `cnt`, `pos` | `instanceID`, `index`, `count`, `position` |
| `cfg`, `db` (new code) | `settings`, `savedSettings` |
| `GetLvl()`, `CalcPos()` | `GetBossLevel()`, `PositionOnArt()` |

Allowed: `i`/`j` loop index, `x`/`y` coordinates, `ns` (the addon namespace, WoW convention),
`ID`, `UI`, `XP`, and Blizzard's own API names (`GameTooltip`, `C_Map`...).
Existing short names are renamed when the file is touched anyway; no rename-only churn.

## 2. One short comment ABOVE, never trailing
- `--` line(s) directly above a function, a block or a tricky line. Never at the end of a line.
- English. No banner headers (`-- =====`), no essays, no restating the next line.
- A comment earns its place when it records a **measurement** ("the visible art is 1002x668 of
  the 1024x768 tiles") or a **trap** ("the map canvas asserts if a pin template has OnEnter").
- File header: 2-4 lines saying what the file is for + the GPL line. Nothing more.

```lua
-- The map canvas calls this only from Blizzard code; on an addon pin it is forbidden.
function Pin:SetPassThroughButtons() end
```

## 3. Short functions. One thing each.
Aim under 20 lines; past 40 it is split, no argument. Name the pieces for what they do:

```lua
function Journal:RenderBossPage()
    self:RenderBossHeader()
    self:RenderLoot()
    self:RenderRelatedQuests()
end
```

## 4. Families: the shared part lives in one place
- **Pull up, do not copy.** The moment two widgets share code, it moves into a shared builder
  (`Widgets.lua`, `Canvas.lua`, a mixin) and both use it. Two copies are a bug waiting to diverge.
- **Mixins for kinds.** A pin/row kind is `CreateFromMixins(BaseMixin)` + only what makes it that
  kind; it overrides named hooks (`OnAcquired`, `Refresh`) instead of re-implementing the base.
- **One file per family**, named after it (`QuestPins.lua`, `LiveView.lua`). A folder appears
  with the second file of a family, not before.
- **Composition over flags.** A row HAS a hover border and a tooltip; it is not a
  `HoverableTooltipQuestRow` copy.

## 5. Nothing dynamic is hard-wired
- A number typed twice belongs in a named constant at the top of the file (or `Theme.lua`).
- Colours, fonts and textures live only in `Theme.lua` (`ns.C`, `ns.Font`, `ns.TEX`).
- Game data (dungeons, bosses, quests, positions, art IDs) lives in `Data/*.lua`, made by a
  generator in `tools/` whenever it comes from a source; screens never type out lists.
- Generated files say `GENERATED by tools/<script>` in their header and are never hand-edited.

## 6. Lua / WoW specifics
- Every file starts with `local addonName, ns = ...`; nothing global except what WoW needs
  (mixins named in XML, slash commands, SavedVariables, AddonCompartment functions).
- Cache frames/regions in fields when created; never look them up by name every frame.
- No `OnUpdate` unless something really moves (drag, animation); events or `C_Timer` otherwise.
- Pool rows; set explicit sizes; measure text only after `SetWidth`.
- Every Blizzard API that may be missing or restricted on this client is reached through a
  guarded alias (see the wow-addon skill).

## Checklist before handing work back
- [ ] No abbreviated names in new/changed code.
- [ ] Every non-obvious function has one short comment above it; no comment restates code.
- [ ] No function over 40 lines.
- [ ] Shared behaviour lives in one place; kinds only override hooks.
- [ ] No colour/texture/number/list typed in a screen file.
- [ ] Syntax check passes and `python -I tools/harness/run.py` is green (also `--combat`).
